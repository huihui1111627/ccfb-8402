# 社保公积金申报 RPA 系统

面向人力外包公司的批量增减员 / 基数调整申报工具：从 Excel 花名册生成待办，Playwright 驱动浏览器在社保、公积金网站逐步申报，每步截图、回执 PDF 归档、结果回写花名册。

**同一人提交两次就是事故**。本系统把「不重复提交」当作硬约束，用四层防线保证：

| 层 | 机制 | 位置 |
|---|---|---|
| 1 | 导入期按业务指纹合并/判重，已成功的指纹不再建任务 | `app/importer.py`、`app/orchestrator.create_task` |
| 2 | 数据库部分唯一索引：同一指纹同一时刻只允许一个 claim | `app/db.py` `ux_tasks_claim` |
| 3 | 每次提交前、以及「结果未知」时，调用站点查询接口按指纹核对 | `app/runner.py` `_reconcile_with_relogin` |
| 4 | 站点侧唯一约束（模拟真实政务系统的幂等受理） | `mock/site.py` |

外加：提交页点下去之后即使超时/掉线，一律走「结果未知 → 只读核对」，绝不直接重试。

## 快速开始

```bash
python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
python -m playwright install chromium     # 首次

./scripts/run_dev.sh                       # mock 站点 :8100 + 控制台 :8000
# 或分别启动
uvicorn mock.server:app --port 8100
MOCK_BASE_URL=http://127.0.0.1:8100 uvicorn app.web:app --port 8000
```

打开 http://127.0.0.1:8000 ，用「花名册导入」上传 `data/demo_roster.xlsx`（`python3 scripts/make_roster.py` 生成）。引擎在控制台进程内启动，会按队列自动执行。

演示账号与数据见 `app/seed.py`：4 家客户企业、8 名在册员工、4 名待增员新人。社保 `C001 / Si#2024C001`，公积金 `C001 / Hf#2024C001`。

## 关键行为

### 0. 企业月配额
- 每家客户在「企业账号」配 `monthly_quota`；本月已成功笔数达到配额后，后续任务停在待执行并标 `quota_exceeded`
- 延后到次日自动重试；调高配额后在控制台点「执行」立刻生效，不需要等

### 1. 从花名册识别增员/减员/基数调整
- 列名别名匹配（企业编码/客户编码/单位编号…，姓名/员工姓名…），跳过表头前的说明行
- 变更类型留空时自动推断：有原基数无新基数 → 减员；有基数变化 → 调整；否则增员
- 身份证 18 位校验位、生效月份格式、基数范围在导入期就拦，坏行进隔离区，不阻塞整批
- 未备案企业编码单独列在隔离区

### 2. 同企业串行、多企业并行
- 调度器按企业维护 `enterprise_busy`，同一企业同时只跑一个浏览器任务
- 全局并发由 `rate_limit_state.global_concurrency` 控制，企业优先级影响出队顺序

### 3. 验证码从 Mock 短信接口取
- 登录前先记录网关当前最大短信 ID，只接受之后到达的验证码，避免复用旧码
- 轮询 `/mock/sms/api/latest`，超时抛 `SmsTimeout`

### 4. 表单中途过期能续上、不重复提交
- 任何表单 POST 后跳登录页 → `SessionExpired`
- 引擎原地重新登录，从第 1 步**重放**到提交受理页；重放不提交
- 提交前做第二道站点核对；提交点击后掉线按「结果未知」核对

### 5. 每步截图、回执 PDF 归档
- 登录、每步表单、提交前、回执页各一张，存 `data/artifacts/task_{id}/attempt_{n}/`
- 回执 PDF = 归档封面（含业务指纹、执行编号、时间）+ 站点原始回执
- `data/receipts/ledger.jsonl` 是哈希链台账，控制台会校验

### 6. 站点校验报错自动归类，改完能重跑
- 按错误码 `E2xx/E3xx/E4xx` 与关键词归到 12 个分类（证件不符、姓名不符、基数超限、已在册、未在册、账号不符、会话过期、限流、结果未知、站点错误、登录失败、字段校验）
- 自动重试类（会话过期、限流、5xx、结果未知）按指数退避重排
- 数据修正类停在「待修正」，控制台改字段后重排队；改证件号/生效月份才会换指纹另建任务

### 7. 月底高峰限流排队
- 队列页一键切「月底高峰」：全局并发降到 2，启用每分钟 20 次令牌桶
- 超出的任务显示「排队中」，不影响幂等与顺序
- 企业月配额用满 → 任务延后到次日并标注 `quota_exceeded`，控制台可调高配额后立即手动执行

### 8. 结果回写花名册
- 原文件只读保存到 `data/roster_in/<batch>/`，绝不修改客户源文件
- 回写生成 `data/roster_out/<batch>/result.xlsx`：原始列 + 申报状态/受理编号/回执路径/错误信息 + 汇总页
- 控制台「下载结果花名册」

## 生产能力缺口

这是可运行的完整演示系统，上真实站点前还需要：
- 账号密码与短信验证码接入真实渠道（KMS / 运营商 API / 人工取码队列）
- Playwright 选择器按真实站点重写（本仓库选择器针对 mock）
- 多 worker 拆分部署（claim 机制已支持，需加进程管理）
- 数据库换 PostgreSQL（SQLite 单写者，200 家客户月底高峰会顶到写锁）
- 控制台加登录与角色权限（当前无鉴权，仅本地使用）
